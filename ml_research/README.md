# ML Research

## Dataset

The production pipeline (`backend/app/ml/pipeline/`) is schema-driven: it
accepts any CSV with `Time`, `Amount`, `V1`-`V28`, and `Class` columns,
which is exactly the shape of the **Kaggle Credit Card Fraud Detection
dataset**.

To train on the real dataset:

1. Download `creditcard.csv` from Kaggle: https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud
2. Place it at `ml_research/data/creditcard.csv`
3. Run the pipeline against it:
   ```bash
   cd backend
   python -m app.ml.pipeline.prepare_data --input ../ml_research/data/creditcard.csv
   ```

## `generate_synthetic_dataset.py`

This environment has no network access to Kaggle, so the pipeline was
built and verified against a **synthetic, schema-matched stand-in**
dataset generated by this script — same columns, same ~0.17% fraud
rate, log-normal `Amount` distribution, PCA-like `V` features with a
deliberately separable fraud/legitimate structure so every pipeline
stage (loading, EDA, cleaning, feature engineering, stratified split,
SMOTE) has real signal to work with.

**This synthetic data is for pipeline verification only.** It is not
a substitute for training a model that needs to generalize to real
transactions — Phase 6 (model training) should be re-run against the
actual Kaggle CSV before any model is treated as production-ready.

Regenerate it any time with:
```bash
python ml_research/generate_synthetic_dataset.py --rows 20000 --output ml_research/data/synthetic_creditcard.csv
```

## `reports/`

`data_preparation_report.json` is written by `prepare_data.py` on every
run — a full audit trail of row counts, class balance, cleaning
actions, feature engineering parameters, split sizes, and SMOTE
resampling stats for that run.
